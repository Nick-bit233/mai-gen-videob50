## 3 Excel 批量自定义导入

### 文件与页面流程

首期支持 `.xlsx`，使用 `openpyxl`，不执行宏或公式。提供舞萌、中二各自的样本工作簿，数据放在 `Sheet1`，另附字段说明。首行是表头，一行是一条谱面记录；用户可以选择其他工作表，不能静默读取错误的表。

在“创建或编辑自定义存档”增加“从 Excel 批量导入”和“导入教学”按钮。教学说明字段、缺失值、成绩单位、枚举别名、路径含义及常见错误，并提供样本下载。

操作顺序为：上传文件并选择游戏及工作表，确认列映射，查看行级预览和曲绘检查结果，再导入到会话中的自定义存档，最后沿用已有“提交存档修改”保存。导入前不写入谱面、成绩或永久曲绘关联。默认按原始行顺序导入；已有编辑中的数据采用明确的“追加”操作，替换已有内容必须由用户主动选择。

### 字段覆盖与默认建议

| 类别 | 标准字段 | 建议缺失处理 |
| --- | --- | --- |
| 曲目 | `song_name`、`artist` | 留空并提示；进入现有必填校验时使用可见的“未命名谱面 第N行”“未知曲师”默认值，允许用户在预览中改正 |
| 歌曲身份 | `song_id` | 作为来源参考可填；写入自定义谱面使用存档范围内的独立 ID，避免更新官方或其他存档谱面 |
| 谱面 | `chart_type`、`level_index`、`difficulty` | 默认普通/SD、MASTER、`?`；明确展示默认，不将未知值冒充已识别值 |
| 舞萌谱面 | `max_dx_score` | `0` |
| 成绩 | `achievement`、`fc_status`、`fs_status`、`play_count` | `0`、`none`、`none`、`0`；不自动补成理论值或全连 |
| 舞萌成绩 | `dx_score`、`dx_rating` | DX 分数默认 `0`；显式 Rating 优先保留，缺失时可按有效成绩与定数计算，否则为 `0` |
| 中二成绩 | `chuni_rating` | 显式 Rating 优先保留，缺失时可按有效成绩与定数计算，否则为 `0` |
| 展示与顺序 | `clip_title_name`、`order_in_archive` | 默认 `Clip_N` 和表格行顺序；顺序列仅在用户选择按该列排序时使用 |
| 曲绘 | `jacket_path` | 留空，使用已有曲绘查找及缺省行为 |
| 视频参考 | `video_path`、视频来源链接/BV、分 P | 留空；填写时复用已有路径和来源校验，不导入任意未经解析的 `video_metadata` 字典 |

覆盖所有现有用户可编辑的谱面和记录业务字段；数据库自增 ID、外键、创建时间等由程序管理。游戏特有字段、非数字定数和现有特殊谱面枚举按 `ChartUtils` 规则处理。配置表中的评论、切片时长和视频样式不混入首期谱面/记录模板。

### 模糊匹配和行级处理

表头匹配按“标准键精确匹配 → 中英文别名字典 → 规范化后匹配 → 相似度候选”递进。规范化处理首尾空格、全半角、大小写和常见分隔符。低置信度候选、同一列可对应多个字段、多列指向同一字段都进入映射确认。特别区分“难度等级”“谱面定数”“达成率”“DX 分数”“Rating”，不能只因文字接近就交换数据含义。

枚举值使用游戏专属别名表，支持中文难度、SD/DX、常见 FC/FS 标签。未知列忽略并列入报告，未知枚举使用可见默认值。对无效数值按行列给出原因与建议默认值，用户可以修正或选择接受默认；不悄悄修剪越界成绩。

曲名模糊查找官方元数据只提供补全候选。只有唯一且通过曲师、谱面类型和难度检查的候选才允许补全；自定义文本优先保留，不把完全自定义谱面强行绑定为官方谱面。首期不自动改写曲名。

读取时处理空行、NaN、前导零、合并表头及百分比单元格。舞萌 `100.5%`、Excel 百分比存储值 `1.005` 需要依据单元格格式转成 `100.5`；无格式的裸数字不猜测其单位。中二成绩按整数分数校验。公式只允许读取已有缓存结果，未缓存时标为缺失并提示用户先保存数值；不能在程序中执行公式。

### 本地曲绘与保存

- 绝对路径指向运行应用的机器；浏览器上传 Excel 不会提供原始本地目录。相对路径必须配合页面上的“曲绘根目录”，教学明确这一点。
- 支持中文、空格和常见图片格式；只读取选定根目录或用户显式填写的本地文件，不展开目录扫描或执行文件内容。
- 路径不存在、图片损坏或超出限制时保留该行，曲绘留空并显示警告。预览显示实际解析路径和加工后的图片。
- 为批次曲绘生成随机文件名，复用裁方、400×400 加工和 `assets` 关联；不依赖原图片持续存在，也不因同名覆盖别的存档。
- 抽出共用提交服务，用事务保存自定义谱面、记录和曲绘关联。文件先准备，数据库提交失败时清理本批次新文件；失败不得留下半个存档或影响已有记录。
- 会话重运行不重复追加，重复行和重复谱面在预览中提示，默认保留为独立自定义记录；用户可明确跳过。正式保存失败可以重试同一批次。

主要文件：`st_pages/Make_Custom_Save.py`、`utils/ChartUtils.py`、`utils/ImageUtils.py`、`db_utils/DatabaseDataHandler.py`，新增独立解析/映射模块及共用自定义记录服务。样本生成脚本和说明纳入版本控制；`.xlsx` 是发布资源，测试及受控 JSON 别名样例需补 `.gitignore` 白名单。

## 4 按线上 release 更新舞萌视频匹配元数据

新增舞萌 release 加载器，协调 `DataUtils`、`video_metadata`、首页及 `PageUtils`，保留现有桌面白名单投影、视频来源解析与手动覆写行为。本期只支持舞萌视频匹配；中二视频继续使用已有搜索流程，歌曲元数据继续使用原有下载与加载路径。

1. 匿名读取一次 `active-release.json`，解析版本标识和公开文件引用。只接受 HTTPS 和配置允许的公开元数据域名/前缀，拒绝路径穿越、带凭据 URL 和跳转到未知主机。
2. 下载该版本下的舞萌谱面、视频清单及发布描述到独立暂存目录。索引可采用相对 object key 或公开 URL，字段适配以实际公开契约为准。
3. 校验 JSON 类型、必须字段、舞萌游戏标识、重复身份、数据关联和各文件版本标识；按已有白名单消费公开 manifest。未就绪或未审核素材不作为可用默认视频。
4. 全部通过后，将本地“当前元数据版本”指针切到完整版本目录，再清除歌曲、视频索引及 Streamlit 缓存。加载函数均通过同一指针解析文件，避免分别替换两个 JSON 留下混合版本。
5. 失败继续使用旧完整版本；首启带内置可用快照。展示当前版本、更新时间、来源及失败原因，允许手动重试；成功后才记更新时间，自动检查沿用每日频率。

已启动的查找或渲染操作固定本次使用的元数据版本。用户手动填写的谱面、成绩、排序、自定义视频与曲绘不因刷新被覆盖。更新完成后也不自动重排存档或改写其 Rating。

中二不会因为索引将来出现相应字段而自动接入视频匹配。页面应明确标示舞萌元数据匹配与中二旧版搜索的区别，两条流程分别进行回归验收。

现有 release JSON 已准备公开且格式兼容时，直接匿名下载即可，不要求另行发布服务端投影。客户端按桌面白名单保留曲目/谱面、发布版本和已审核的公开视频来源字段；不使用内部视频存储字段获取私有视频或附带 OSS 身份。需要保留原始 JSON 私有时，才选用独立公开投影目录。该仓库负责客户端，实际 OSS 读取权限和同版本文件的备齐由发布侧提供。

## 5 错误诊断和用户手动提交

### 本地诊断包

新增共用诊断模块。每次导入、更新或渲染生成一个运行 ID，关联 Python 异常链和相关子进程；成功但发生硬件回退的任务同样保留诊断。

每次 FFmpeg 尝试记录阶段、参数数组、输入输出映射、开始时间、耗时、退出码（十进制和 Windows 十六进制）、完整 stdout/stderr，以及启动失败/超时/BrokenPipe 的异常链。覆盖 `_run_subprocess_checked`、编码回退、硬件探测、`FFmpegWriter` 和最终 concat；首轮硬件失败不得被软件成功或后续失败覆盖。

对每个实际参与拼接的片段缓存一次 `ffprobe` 结果，记录 codec、尺寸、pix_fmt、帧率、时间基准、SAR、时长、音轨、采样率及声道。环境记录应用版本、实际 Python/FFmpeg/FFprobe 路径与版本、显卡型号、驱动版本（可取得时）、Taichi 后端及输出配置。日志目录独立于会被清理的转场临时目录，按体积和保留时间清理，完整 stderr 写文件而非长期留在内存。

页面显示错误摘要、原始错误片段、诊断包下载和“提交错误报告”。应用启动前的失败由启动器保留 stdout/stderr 和最小环境诊断；应用恢复启动后可提交这份记录。

### 上传流程与内容

“提交错误报告”打开预览，展示将发送的文件、大小和可选问题描述，用户点击“确认提交”后才上传。无自动上传、无启动时补传；离线或上传失败仍可下载本地包。一次确认绑定固定报告 ID，成功后当前会话禁用再次提交，Streamlit 重运行不再次上传。网络重试使用同名对象，409 不下载核对、不覆盖、不声称提交成功。

完整原始诊断留在本机；上传包使用脱敏副本，保留各次尝试和完整错误正文结构，替换绝对用户路径、用户名、Cookie、Token、代理认证、邮箱、签名 URL 查询参数及密钥。输入以 `clip_0004` 等一致标签关联。白名单输出环境和渲染配置，不打包数据库、视频、曲绘、Excel 原文件、完整配置或浏览器数据。无论日志最终是否公开读取，都必须验证含敏感字符串用例的脱敏结果。

### 独立日志桶

1.2.8 确定采用直接匿名前缀授权。独立标准存储桶为 `nickbit-maigen-report-logs`，Bucket ACL 设为 `private`，Object ACL 使用 `default/private`。以 Bucket Policy 仅对该桶 `reports/*` 授予所有访问者 `oss:PutObject`；不授予匿名读取、列举、删除、修改 ACL、桶管理或前缀外读写权限。客户端仅配置公共 endpoint 和前缀，使用应用服务端 Python 发出 HTTPS 请求。

该前缀属于公共访问；收尾配置阶段核对 OSS 全局及目标桶的“阻止公共访问”是否会阻止该授权，并按确认的范围配置。其他桶使用各自的访问保护，日志桶无需设置桶级 `public-read-write`。规则与层级见 [OSS 阻止公共访问](https://www.alibabacloud.com/help/zh/oss/user-guide/block-public-access)。

对象名为 `reports/YYYY/MM/DD/{report_id}.zip`，使用随机报告 ID。上传带禁止同名覆盖参数，网络超时后沿用同一个对象名重试；只写模式下无法核实远端内容，409 提示维护者核对，成功的 PUT 才展示提交成功及 OSS 请求编号。随机文件名、客户端禁止覆盖及大小限制用于避免正常使用时的重复和误操作，桶配置验收记录实际权限与覆盖行为。

初始建议上传包最大 10 MiB，超限保留本地完整包并提示下载，不能为了上传而默默截掉首轮错误。保留诊断白名单和基本凭据过滤，日志仅作错误反馈。客户端提交频率、桶侧保留期及费用告警在收尾配置阶段补齐。

日志桶已由用户创建并配置为匿名只写，公共 endpoint 为 `https://nickbit-maigen-report-logs.oss-cn-shanghai.aliyuncs.com`。本地 HTTP 服务覆盖成功、403、超时、重复提交和超限情况；线上验收检查真实匿名 PUT 成功、GET/HEAD 被拒绝和其余权限范围。线上地址未配置时仍显示“下载日志”和明确的配置提示，不进行在线请求。

按前缀授权的依据见 [OSS Bucket Policy](https://www.alibabacloud.com/help/zh/oss/user-guide/use-bucket-policy-to-grant-permission-to-access-oss/)，覆盖语义见 [PutObject](https://help.aliyun.com/zh/oss/developer-reference/putobject)。本期按此方案提供桶策略说明和客户端配置，不包含接口中转服务。

## 6 Python 启动隔离修复

`ModuleNotFoundError: No module named '_distutils_hack'` 可能来自其他 Python 的搜索路径或 `.pth` 钩子，也可能是打包遗漏、旧 runtime 覆盖升级不完整。先记录实际 `sys.executable`、`sys.prefix`、`sys.base_prefix`、`sys.path`、相关环境变量和模块位置，按证据区分；不把同一个模块缺失错误当成已证明的根因。

- 正式启动使用包内解释器绝对路径，在启动器的 `setlocal` 范围内清空外部 `PYTHONHOME`、`PYTHONPATH` 等影响导入的设置。检查所有 Python 子进程，使用当前解释器而非 PATH 中的 `python`。
- 验证并随包携带正确的 `python312._pth`，仅包含包内标准库、依赖和应用根目录；检查包内 `sitecustomize`、`.pth` 和 setuptools 安装是否完整，尤其是 `_distutils_hack` 与 `distutils-precedence.pth` 的配套关系。
- 评估正式入口显式 `-I`；项目根目录必须通过受控的 `_pth` 或启动引导加入。`-I` 会忽略 `PYTHON*` 环境变量，UTF-8 使用显式 `-X utf8`，不能继续只依赖 `PYTHONUTF8=1`。隔离效果参考 [Python 3.12 启动选项](https://docs.python.org/3.12/using/cmdline.html)。
- 构建、解压后和运行前检查关键依赖完整性，包含 `_distutils_hack`、setuptools、Streamlit 和应用模块；缺失时提示更换完整 runtime，并保留启动日志。
- 正式升级明确完整替换 runtime，避免在用户系统 Python 安装包作为修复，也不在启动时临时 pip 安装掩盖包缺失。

验收注入指向另一 Python 的 `PYTHONHOME/PYTHONPATH`、用户 site-packages 中的冲突包、优先 PATH 中的其他解释器、带空格/中文安装目录和从其他工作目录启动。另测缺失 `_distutils_hack`、缺失 `_pth`、残留旧 `.pth` 的包，要求得到可定位的错误或正确隔离。主进程与 Taichi 探测子进程都必须验证。

主要文件：`scripts/runtime-start.bat`、`scripts/build_runtime.py`、约束文件，以及需要的最小启动引导；沿用 `verify_runtime.py`、`verify_runtime_ui.py` 的独立目录验收方式。

## 7 Transition island 和硬件编码兼容

### 先区分失败阶段

GPU 图像合成、输入视频解码、H.264 编码、转场滤镜和最终 concat 分别记录结果。`h264_nvenc` 属于编码器，NVDEC/CUDA 解码及 Taichi 计算能力需要各自验证；Taichi 能运行不等于该 GPU 能完成 NVENC。驱动和 GPU 能力检查参考 [NVIDIA FFmpeg 指南](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/ffmpeg-with-nvidia-gpu/index.html)。

现有 `detect_hw_encoder` 已执行短实际编码探测，但探测参数与真实 `get_ffmpeg_encoder_args` 不完全相同，失败只打印最后一行。应改为统一探测与正式参数、保留完整结果，并在诊断页面提供“检查硬件编码”按钮。探测成功也不能代替本次真实分辨率、帧率和媒体链路的验收。

### 可直接推进的输入兼容工作

- 在拼接前读取 `ffprobe`，定位到具体片段和相邻转场，验证尺寸、时长、解码可用性及音轨。复用当前主题配置快照；旧片段、损坏片段或媒体探测不符时明确要求重生成。
- 转场主体和窗口统一到本次输出的分辨率、SAR、像素格式、CFR 和时间基准，缩放保持比例并补边；补帧/补音频规则覆盖短片段和时长差，不能仅靠切换编码器修复滤镜输入。
- 没有音轨时为对应窗口补齐等长静音，再执行 acrossfade；已有音轨保持原内容，统一采样率和声道。
- 正常转场失败不静默丢弃转场；保留用户选定的时长和低内存逐对处理方式，错误提供重新生成及下载诊断包入口。
- 最终成片先写独立临时输出，媒体验证通过才替换最终文件；失败保留已有成品和该次诊断，不把残缺 MP4 当成功。

`xfade` 要求输入恒定帧率，并匹配分辨率、像素格式、帧率和时间基准，参见 [FFmpeg 输入要求](https://ffmpeg.org/pipermail/ffmpeg-cvslog/2021-April/127243.html)。历史本地复现曾发现尺寸不同、缺音轨均可让硬件与软件尝试失败；当前反馈用户的具体原因仍待其现场诊断确认。

### 按诊断结果修复硬件问题

错误分类至少区分：编码器不在构建中、设备不支持、驱动/API 不兼容、参数或像素格式不支持、设备/会话资源不足、输入/滤镜失败、输出权限或空间不足。保留原错误原文，无法归类时标为未知，不推断成某一驱动问题。

首个确证的编码器能力失败可在当前任务内停止重复尝试该编码器，软件编码继续完成并显示回退原因；不能将某一对输入的滤镜失败缓存成“整台机器无 NVENC”。下次任务或用户重新检查时允许重试。兼容参数调整或 runtime FFmpeg 更新按真实错误推进，不为了消除警告无条件强制软件编码。

若无法复现用户的 Transition island/NVENC 故障，本版本交付完整本地诊断、手动提交、已验证的输入兼容修复和现有软件回退；该用户问题在版本说明中保持“待现场报告定位”，不能标成全部修复。
