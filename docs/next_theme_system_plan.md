# 下一版本：新版主题系统开发计划

日期：2026-09-18。状态：已实现并完成本地短样本验收，分支 `codex/new-theme-system`。实现说明和证据见 [theme_system.md](theme_system.md)。版本号另行确定。

## 1. 目标与已确认选择

本版本交付三项功能：

1. 片头、片尾分别配置 BGM，更新现有视频主题的默认配对，并分别支持本地上传与试听。
2. 新增 maimai MAGiCAL 视频主题及页面配色，参考 SaaS 2026-09-17 的正式素材和配色实现。
3. 中二节奏新增“定数展示选项”：国服、最新、定数对比。单版本展示使用独立版本 Logo 和对应布局，定数对比保持现有显示行为。

**用户已确认：舞萌沿用 SaaS 的默认 BGM 配对，中二主题的配对由用户补充。**

实施范围为当前桌面版仓库。SaaS 仅作代码、配色和素材来源参考。本版本不扩展为通用主题插件系统，不引入 SaaS 服务依赖。

建议沿用现有的按游戏保存视频样式、独立选择页面配色的方式。新增 MAGiCAL 不自动替换已保存主题；更改展示方式不重排分表、不修改存档成绩。等级标识联动及缺失值规则已确认，见第 10 节。

## 3. 配置与兼容方案

继续使用 `static/video_style_config.json` 的按游戏结构，增加小范围扩展：

```json
{
  "chunithm": {
    "style_schema_version": 2,
    "style_name": "Verse",
    "base_style_name": "Verse",
    "asset_paths": {
      "intro_bgm": "./static/assets/audios/intro_chunithm_verse.mp3",
      "ending_bgm": "<用户确认后的片尾素材路径>"
    },
    "options": {
      "chunithm_constant_display": "compare"
    }
  }
}
```

示例仅列新增或相关字段；保留原有素材路径、字体和文本样式。`ending_bgm` 与现有 `ending_configs` 命名保持一致。`base_style_name` 用于自定义后仍能恢复相应主题默认音乐。

兼容规则：

- 新建统一的样式补全/校验函数，供页面读取、预览与渲染共用，避免只有某条路径认识新字段。
- 老配置缺少 `ending_bgm` 时，片尾沿用该配置的 `intro_bgm`；保持用户原有自定义音频。新应用预设时才采用新版默认配对。
- 老配置缺少定数选项时使用 `compare`。非法枚举显示明确提示，不静默生成另一种布局。
- 旧 `Custom` 若无法识别来源主题，保留全部原值；需要恢复主题默认值时让用户选择基础主题。
- 配置读取时在内存中补全，正常保存时写入新字段；采用临时文件后替换，避免保存中断损坏配置。
- 默认主题使用显式常量，保留各入口原先的默认选择，避免新增列表项改变行为。是否统一这些默认值不列为本次必要改动。
- 只切换 Verse/X-Verse 时保留定数展示偏好；明确重置样式时恢复“定数对比”。

上述方案不要求新增数据库业务字段或迁移既有成绩数据。

### 4.2 页面行为

- 在现有样式页分别设置“片头背景音乐”“片尾背景音乐”，每项显示当前文件、试听、上传和恢复该主题默认音乐。
- 继续支持 MP3/WAV；用户可以给两段选择同一首，也可以只修改其中一段。
- 上传时实际探测音轨和有效时长，拒绝空文件、损坏文件或没有可解码音轨的文件，失败保留原设置。
- 使用独立随机文件名及游戏/用途目录保存上传文件，保留原名用于显示，避免两个上传槽及两种游戏互相覆盖。无需计算文件 hash。
- 恢复某一段默认音乐只修改该配置引用。检查现有“重置全部”清理范围，避免误删其他游戏仍引用的上传文件。
- 本期不要求完整迁入 SaaS 音乐库、裁剪编辑器、每页连续播放或独立音量控制。

### 4.3 渲染与播放规则

- CPU/GPU 生成器都显式接收 `section="intro" | "ending"`，通过同一个解析函数选择音频；不从片段标题推断类型。
- 覆盖整片生成、分段生成、GPU 分段及整片调用、样式预览等入口；预览明确支持 ending。
- BGM 从头播放；长于片段则截断，短于片段则循环至片段结束。多页片头/片尾保留现有“每段重新开始”的行为。
- GPU 的循环只作用于信息片段 BGM，不改变正片谱面视频音频；继续沿用既有音量均衡与转场设置。
- 配置明确指定的音频文件缺失时给出可定位的错误，避免 CPU 报错而 GPU 静默生成无声片段。

## 6. 中二节奏定数展示

### 6.1 交互与数据含义

在中二的“生成成绩背景图片”区域加入“定数展示选项”，选项顺序为“国服 / 最新 / 定数对比”，默认“定数对比”。保存到中二样式的展示选项，并让样式预览使用相同设置。

| 选项 | 内部值 | 数据规则 | 定数区展示 |
| --- | --- | --- | --- |
| 国服 | `cn` | 严格读取 `level_value_cn` | 国服 Logo + 单个定数，不显示比较箭头 |
| 最新 | `latest` | 严格读取 `level_value_latest` | 最新版 Logo + 单个定数，不显示比较箭头 |
| 定数对比 | `compare` | 沿用当前 `ds_cur` / `ds_next` 兼容逻辑 | 两个 Logo、两列定数，保留 `↑ / ↓ / →` |

“最新”表示当前已加载的融合元数据里的最新版本字段，不隐含联网刷新。当前模板标注为“中二节奏 2027 / CHUNITHM Mate”；发布素材与元数据需要一起核对，不能仅改 Logo 就声称完成定数更新。

已确认的缺失处理：单版本没有对应有效定数时显示 `--`，不借用另一版本冒充。存档中的自定义 `difficulty` 没有明确版本来源时，也不直接填到国服或最新名下；需要保留自定义定数的体验时再明确版本来源规则。

实现时增加明确的国服/最新原始字段（例如 `ds_cn`、`ds_latest`）供单版本取值，保留 `ds_cur`、`ds_next` 支持旧对比行为。抽出两处图片数据转换共用的组装函数，但不修改其他调用方依赖的全局回退工具。

左侧等级标识（如 14+）建议跟随单版本选项；对应定数缺失时显示未知等级。对比模式仍采用现有等级规则。此项已由用户确认；单曲 Rating、分数和顺序保留原存档值。

### 6.2 图片素材与动态布局

将“固定底图 + 两处数字”改成“中性底图 + 定数区域标题 + 版本 Logo + 数值”的合成方式：

1. 准备不含版本 Logo 和“定数变动”标题的中性成绩底图，保留其余装饰、评论区、分数及 Rating 区。
2. 增加透明 PNG Logo，例如 `Chunithm/Logos/cn_2027.png`、`Chunithm/Logos/latest_mate.png`。具体命名及裁切边界在素材整理时确定。
3. 对比模式保留“定数变动”标题与双列布局；单版本改为“谱面定数”标题，将一个 Logo 和一个数值居中于右下定数区域。
4. 布局表统一管理 Logo 的容纳框、数字锚点、字号和标题。对比模式以原有两个数字锚点为基准；单列中心暂取右下区域中心约 `x=1662`，最终按样图调整。
5. Logo 等比缩放并用 alpha 合成，避免拉伸；切换模式后不应残留另一版本的 Logo、数字、箭头或“定数变动”标题。
6. `ChuniImageGenerater` 使用配置中的 `score_image_base`，消除当前硬编码底图路径；将显示选择和布局绘制拆为小函数供预览与批量生成共用。

中性底图和独立 Logo 尚未在当前素材目录中发现，是实施阶段的明确交付项。若只能取得现有合成底图，需先完成拆层样图确认；不能用不匹配背景的色块遮盖当作最终素材。

## 7. 已有图片与视频片段的更新

必须避免出现“设置已保存，但成片还是旧 BGM / 旧定数布局”：

- 为新生成的图片批次和视频片段记录轻量配置快照，包括展示选项、相关主题素材版本、音频引用及图片批次标识；通过字段直接比较判断是否需要重生成，不计算文件或状态 hash。
- 定数模式变化后将相关成绩图片标记为需要重新生成；视频生成前检查当前存档图片与所选模式一致。
- 只有 BGM 变化时，更新受影响的片头或片尾片段；无需要求用户重新生成成绩图或重新下载谱面视频。
- 底图、字体、定数布局变化时，更新受影响图片和曲目片段；已有最终视频在用户重新生成前保留。
- 同名视频片段的跳过逻辑必须检查配置快照；旧片段没有快照时不能认定已与新配置一致，应明确提示重新生成。
- 新图片批次成功后再发布路径及完成标记；生成失败不把部分新图标为整批完成。渲染失败沿用原有的旧成品保护。

此处只追踪本次功能所需的配置与产物关系，不建立通用历史状态重建或完整缓存框架。
